0. El mapa mental: Laravel por dentro

Laravel es "convención sobre configuración", como Spring Boot pero en PHP. El ciclo de una petición:

Navegador  →  public/index.php
            →  bootstrap/app.php      (registra rutas, middleware, manejo de errores)
            →  routes/web.php         (¿qué código atiende esta URL?)
            →  Componente Livewire    (app/Livewire/*.php)  ← aquí vive tu lógica de UI
            →  Servicio               (app/Services/*.php)   ← reglas de negocio
            →  Modelo Eloquent        (app/Models/*.php)     ← habla con la DB (SQLite)
            →  Vista Blade            (resources/views/*.blade.php)

1. Arranque: bootstrap/app.php

Aquí se decide qué archivos de rutas existen y qué middleware global se aplica. Casi no se toca.

return Application::configure(basePath: dirname(__DIR__))
    ->withRouting(
        web: __DIR__.'/../routes/web.php',
        api: __DIR__.'/../routes/api.php',      // ← habilita /api/*
        commands: __DIR__.'/../routes/console.php',
        health: '/up',
    )
    ->withMiddleware(fn ($m) => null)
    ->withExceptions(function ($e) {
        $e->shouldRenderJsonWhen(fn ($r) => $r->is('api/*') || $r->expectsJson());
    })->create();

2. Rutas: routes/web.php

Una URL apunta a un componente Livewire (la clase PHP), no a un "controller" con muchos métodos. Ese es el rasgo distintivo de esta app.

Route::middleware(['auth'])->group(function () {
    Route::get('learn',        LearningPath::class)->name('learn');
    Route::get('lesson/{lesson}', LessonPlayer::class)->name('lesson.play'); // {lesson} = modelo Lesson (route-model binding)
    Route::get('shop',         Shop::class)->name('shop');
    Route::get('leaderboard',  Leaderboard::class)->name('leaderboard');
    Route::get('progress',     Progress::class)->name('progress');
});
Route-model binding: {lesson} se convierte automáticamente en un objeto Lesson buscado por id. Si no existe → 404. Como @PathVariable + repositorio, pero gratis.

3. Livewire: la pieza clave (esto es lo que más te enseña)

Livewire permite UI interactiva sin escribir JavaScript: el estado y los métodos viven en una clase PHP; cada interacción del usuario hace una petición y Livewire re-renderiza solo lo necesario. Piensa "React pero el componente corre en el servidor".

Ejemplo real: app/Livewire/LessonPlayer.php.

class LessonPlayer extends Component {
    public Lesson $lesson;      // propiedad pública = "estado" reactivo
    public int $index = 0;
    public $selected = null;
    public ?bool $correct = null;

    public function mount(Lesson $lesson): void { /* init */ }

    public function submit(LessonRunner $runner): void {   // ← inyección por método (DI)
        $answer = match ($this->...type) { ... };
        $result = $runner->answer(auth()->user(), $exercise, $answer);
        $this->correct = $result['correct'];               // cambiar estado = re-render automático
    }
}

La vista resources/views/livewire/lesson-player.blade.php usa directivas que conectan HTML ↔ PHP:

<button wire:click="submit">Comprobar</button>   <!-- llama al método submit() -->
<input wire:model="text">                        <!-- two-way binding con $text -->
@if ($correct) <p>¡Correcto!</p> @endif          <!-- render condicional (como JSX) -->
Ejercicio de aprendizaje: abre LessonPlayer.php y lesson-player.blade.php en paralelo. Verás que $this->score++ en PHP se refleja en pantalla sin que escribas un solo fetch().

4. Eloquent (ORM): app/Models/*.php

Cada modelo = una tabla. Las relaciones son métodos que devuelven tipos claros.

class User extends Authenticatable {
    public function courses(): BelongsToMany {
        return $this->belongsToMany(Course::class, 'user_courses')->withPivot('is_active');
    }
    public function streak(): HasOne { return $this->hasOne(Streak::class); }

    public function totalXp(): int {                       // método de dominio, no columna
        return (int) $this->xpEvents()->sum('amount');
    }
}

5. Migraciones: database/migrations/

El esquema se versiona en código, igual que Flyway/Alembic. Ejemplo de ..._create_competition_tables.php:

Schema::create('league_members', function (Blueprint $table) {
    $table->id();
    $table->foreignId('league_id')->constrained()->cascadeOnDelete();
    $table->foreignId('user_id')->constrained()->cascadeOnDelete();
    $table->unsignedInteger('weekly_xp')->default(0);
    $table->unique(['league_id', 'user_id']);
});
php artisan migrate:fresh --seed   # reconstruye la DB y la siembra (como alembic upgrade + seed)

6. Servicios (reglas de negocio) + Inyección de Dependencias

Aunque Livewire ya es una clase, la lógica de negocio se saca a app/Services para poder testearla sin UI — exactamente el patrón @Service en Spring.

class LessonRunner {
    public function __construct(
        private ExerciseEngine $engine,          // ← Laravel inyecta estas clases solo
        private GamificationService $gamification,
        private LeagueService $leagues,
        private AchievementsService $achievements,
    ) {}

    public function complete(User $user, Lesson $lesson, int $score): array {
        $this->gamification->awardXp($user, $lesson->xp_reward, 'lesson', $lesson);
        $this->gamification->touchStreak($user);
        return $this->achievements->evaluate($user);   // devuelve logros desbloqueados
    }
}
Clave de DI en Laravel: no declaras new LessonRunner() en ningún lado. Pides el tipo en el constructor o en el método y el service container lo construye. Es el ApplicationContext de Spring, activado por defecto.

8. API + Resources: JSON con forma controlada

Breeze usa Blade (HTML) para web, pero también exponemos una API tipo Duolingo. Un Resource transforma el modelo → JSON (como un DTO).

class CourseResource extends JsonResource {              // app/Http/Resources/CourseResource.php
    public function toArray(Request $request): array {
        return [
            'learning_language' => $this->toLanguage?->code,   // snake_case, como la API real de Duolingo
            'num_learners'      => (int) $this->userCourses()->count(),
            'phase'             => 1,
        ];
    }
}

9. Tests: tests/Feature/*.php

Los tests corren contra una DB limpia (RefreshDatabase). Comparan comportamiento, no implementación.

class ApiTest extends TestCase {
    use RefreshDatabase;

    public function test_courses_endpoint_returns_flat_list_in_duolingo_shape(): void {
        $json = $this->getJson('/api/v1/courses')->assertOk()->json();
        $this->assertArrayHasKey('learning_language', $json[0]);
    }
}

10. Tu ruta de lectura recomendada (de lo simple a lo complejo)

  1. routes/web.php — entiende el mapa de URLs.
  2. app/Livewire/LessonPlayer.php + su blade — el concepto estrella (Livewire).
  3. app/Services/ExerciseEngine.php — lógica pura y testeable, con match() (el "switch expression" de PHP).
  4. app/Models/User.php + Course.php — relaciones Eloquent.
  5. database/migrations/ — cómo se modela el esquema.
  6. tests/Feature/ApiTest.php — cómo se prueba una API.
  7. app/Services/LessonRunner.php — orquestación e inyección de dependencias.

11. Chuleta de comandos

php artisan serve                 # levantar el servidor
php artisan route:list            # ver TODAS las rutas
php artisan migrate:fresh --seed  # recrear DB + datos demo
php artisan test                  # correr tests
php artisan tinker                # REPL con tu app cargada (como `python`/`jshell`)
php artisan make:model Foo -m     # generar modelo + migración
php artisan make:livewire Foo     # generar componente Livewire
Nota (PHP vs lo que conoces): -> = acceso a objeto (como . en Java/Python). :: = método/constante estática o de clase. => = clave→valor en arrays. $ = variable. Los tipos se declaran con : int al final (return type) o antes de la variable.
